internal/limiter/fixed_window.go — Lua script ensures atomicity
const fixedWindowScript = ` local key = KEYS[1] local limit = tonumber(ARGV[1]) local window = tonumber(ARGV[2]) local count = redis.call('INCR', key) if count == 1 then redis.call('EXPIRE', key, window) -- set TTL on first request end if count > limit then return {0, 0, redis.call('TTL', key)} -- denied end return {1, limit - count, 0} -- allowed ` // INCR + EXPIRE execute as one atomic unit. // No other Redis command can interleave between them. // This is why we use Lua — not separate GET + SET.
Core Logic

Four algorithms, one interface

Swap algorithms via a single environment variable. The Limiter interface abstracts everything — callers never know which algorithm is running.

Fixed Window Counter
SIMPLE

Counts requests in fixed time buckets. Cheapest memory footprint. A new window starts on schedule regardless of traffic.

Sliding Window Log
PRECISE

Tracks exact timestamps in a sorted set. The window slides with every request — no boundary burst possible.

Token Bucket
BURST

Refills tokens at a steady rate. Allows controlled bursting — callers can save unused capacity and spend it later.

Leaky Bucket (GCRA)
SMOOTH

Generic Cell Rate Algorithm. Enforces strictly uniform output rate by storing a theoretical arrival time (TAT).
